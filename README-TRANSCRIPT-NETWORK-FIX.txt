ScriptFlow Pro - Transcript Studio and Firebase Connectivity Fix

ROOT CAUSE
----------
The deployed ScriptFlow package contained a launcher-only transcript-studio.js that replaced the full Transcript Studio implementation. This removed the Studio runtime from the current codebase. The launcher itself still pointed to the requested Render URL, but the full Studio implementation was no longer retained for backward compatibility/in-app use.

FIX
---
1. Restored the complete Transcript Studio runtime into src/transcript-studio.ts and js/transcript-studio.js.
2. Existing Transcript Studio buttons still redirect directly to:
   https://transcript-studio-n0nv.onrender.com/
3. The full TranscriptStudio object remains exposed for existing/in-app integrations.
4. Enter/Space keyboard activation is preserved.

FIREBASE ERRORS
---------------
ERR_BLOCKED_BY_CLIENT and Chrome extension asynchronous listener messages are browser/client-level errors and cannot be repaired by application JavaScript. The app now handles Firestore connectivity failures more safely: it enters local-data mode, stops failed realtime listeners, avoids treating expected connectivity errors as fatal application errors, and retries when browser connectivity returns.

IMPORTANT
---------
If the browser/network blocks firestore.googleapis.com or securetoken.googleapis.com, cloud synchronization cannot work until that block is removed. Local data remains available. If Chrome reports a chrome-extension:// message-channel error, test with extensions disabled; that message is generated by an extension, not ScriptFlow Pro.

BUILD
-----
npm install --include=dev --no-audit --no-fund && npm run build

START
-----
npm start
